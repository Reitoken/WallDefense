Vue d'ensemble

Wall Defense — tower defense incarné, vue top-down : une héroïne défend son mur contre des vagues de monstres dimensionnels en switchant entre 7 armes élémentaires. 30 stages (6 zones), 3 modes, stage infini.

Architecture : composants indépendants · communication par délégués · DataAssets comme ponts de données · UI event-driven · debug-first. Référence complète : ArchitectureTechnique.md.

Étape 1 — Ce qui est implémenté ✓

WDTypes.h — le vocabulaire commun du jeu livré

Les types que tout le jeu utilisera, sans aucune dépendance :

TypeRôle
EWDElementLes 7 éléments (Normal, Feu, Glace, Foudre, Vent, Lumière, Ténèbres).
EWDDifficultyLes 3 modes : Normal, Hard, Enfer.
EWDElementalMatchLe verdict d'un impact : Neutre / Faiblesse / Résisté — alimentera les chiffres de dégâts (grande icône / petite + flèche).
FWDDamageEventUn paquet de dégâts : montant, élément, auteur, point d'impact.
FWDElementalProfileL'identité élémentaire d'un monstre : UNE faiblesse, N résistances. Règle codée : Normal n'est jamais résisté.
UWDTypeLibraryGetElementColor() — LA couleur de chaque élément, partagée par le debug, les VFX et l'UI.
UWDHealthComponent — le composant de vie universel livré + 10 tests

Un seul composant de vie pour tout (mur, monstres) :

Dégâts appliqués = Montant × MultiplicateurÉlémentaire × 100 / (100 + Défense)
   Faiblesse  : ×1,75        Résistance : ×0,5        Neutre : ×1
   Le BOUCLIER absorbe d'abord, la vie ensuite.

Événements exposés (quiconque peut écouter, le composant ne connaît personne) : OnHealthChangedOnShieldChangedOnDamaged (+ verdict élémentaire)OnShieldBrokenOnDied

API : ApplyWDDamage · Heal · AddShield · Kill · ResetToFull · GetElementalMatch. L'ancien HealthComponent reste en place pour le contenu existant ; la migration se fera avec les monstres (étape 4).

UWDDebugSubsystem — le dessin debug centralisé livré

Tout le gameplay dessinera à travers lui : lignes de tir, sphères de projectiles, cercles de zones au sol, impacts, chaînes entre cibles, textes flottants — colorés par élément.

Une seule commande console contrôle tout : wd.Debug.Draw 0/1. Désactivé → tous les appels deviennent des no-ops, les appelants ne vérifient jamais rien.

Étape 2 — Ce qui est implémenté ✓

AWDHeroCharacter — l'héroïne top-down livré

Twin-stick : elle se déplace librement ET vise indépendamment — elle peut courir vers le mur en tirant derrière elle. La rotation suit la visée (interpolation douce), jamais le déplacement. Caméra Zelda-like embarquée (vue plongeante à −62°, distance et angle réglables dans les Détails). En attendant son mesh, une flèche de debug montre où elle regarde.

Elle ne peut pas mourir (seul le mur compte). Vitesse 600 uu/s. Expose l'état d'animation : GetSpeed, IsMoving, GetMoveDirectionAngle (angle vélocité/regard pour le blendspace de strafe).

AWDHeroController — deux schémas de contrôle livré
ActionClavier + sourisManette (cible principale)
Se déplacerZQSD et WASD (les deux mappés)stick gauche
Viserla souris (le perso regarde le curseur)stick droit (prioritaire dès qu'il est poussé)
Tirer (placeholder)clic gauchegâchette droite
Changer d'arme (placeholder)molette / TabRB

Enhanced Input construit en C++ au runtime — zéro asset nécessaire (le remapping de l'étape 6 reprendra ces actions). La visée souris fonctionne par intersection du curseur avec le plan du sol : pas besoin de collision.

UWDHeroAnimInstance + AWDSandboxGameMode livrés

AnimInstance : la future AnimBP de l'héroïne héritera de cette classe — Speed, bIsMoving, MoveDirection (et bIsFiring dès l'étape 3) sont déjà exposés à l'AnimGraph, aucune logique à câbler en Blueprint.

GameMode sandbox : spawne l'héroïne + son contrôleur dans n'importe quelle map de test.

Comment tester dans Unreal — Étape 2

Piloter l'héroïne (5 minutes)

1. File → New Level → Basic (il y a déjà un sol). Sauvegarde-la (ex. L_Sandbox).
2. Window → World Settings → GameMode Override → WDSandboxGameMode.
3. Play (PIE). Tu incarnes une capsule grise avec un nez conique (le nez = son regard) + une ligne de debug de visée. Pas de PlayerStart dans la map ? Le GameMode en crée un automatiquement — impossible d'avoir un écran vide.

✅ À vérifier au clavier/souris : ZQSD (ou WASD) déplace ; la capsule regarde le curseur en permanence — déplace-toi dans un sens en visant l'autre ; clic gauche = tir de debug vers la visée ; molette/Tab = cycle des 7 éléments (le nom + un cercle coloré apparaissent — c'est la palette officielle).

✅ À la manette : stick gauche déplace, stick droit vise (il prend la priorité sur la souris dès qu'il est poussé), gâchette droite tire, RB change d'élément.

✅ Caméra : vue plongeante fixe qui suit le personnage sans tourner. Angle/distance réglables sur le pawn (sélectionne-le en PIE : CameraPitch, CameraDistance).

AWDProjectile + pool — les comportements sont des données livré

UN seul projectile générique : perçant (N cibles), rebond (sur la géométrie), fragments (anneau de sous-projectiles à l'impact — qui ne re-fragmentent jamais), chaîne (saute de cible en cible), autoguidé (virage limité). Tout vient des données de l'arme — les paliers 1–100 ne feront qu'activer/amplifier ces comportements. Pool de projectiles (UWDProjectilePoolSubsystem) : zéro spawn au tir après préchauffage.

AWDTargetDummy — les cibles d'entraînement livré

Des cubes teintés de la couleur de leur FAIBLESSE (tire avec l'élément assorti !), PV affichés au-dessus, chiffres de dégâts colorés par élément avec « FAIBLESSE ! » / « résisté v », bouclier visible, K.O. puis réapparition en 2 s. Le sandbox en spawne 3 automatiquement : faible Feu · faible Glace (résiste Feu) · bouclier + faible Lumière.

Comment tester dans Unreal — Étape 3

La boucle de tir complète (10 minutes)

1. Ouvre L_Sandbox (GameMode Override déjà sur WDSandboxGameMode) et Play.
2. 3 cubes colorés t'attendent : leur couleur = leur faiblesse.

✅ Le switch (molette/Tab/RB) : le nom de l'arme s'affiche, la ligne de visée prend la couleur de l'élément.
✅ Fusil (gris) : maintiens le clic — tir soutenu, « 10 » sur les cibles.
✅ Lance-flammes (orange) : cône continu courte portée — approche-toi. Sur le cube orange : « FAIBLESSE ! » (7 par tick) ; sur le cube bleu : « résisté v » (2).
✅ Arc électrique (jaune) : touche un cube proche d'un autre — l'éclair chaîne (segment jaune entre les deux).
✅ Tornade (turquoise) : lente et large, elle traverse plusieurs cibles alignées.
✅ Frappe céleste (blanc) : un cercle se télégraphie au curseur, la colonne tombe après 0,6 s. Sur le cube à bouclier : ça fond — c'est l'arme anti-bouclier (faiblesse).
✅ Laser sombre (mauve) : un trait épais qui transperce TOUTE la ligne et rebondit sur les murs (mets un mur/cube statique pour le voir). Gros cooldown : switch en attendant.
✅ Le bouclier du 3e cube absorbe d'abord ([Bouclier 50] au-dessus), puis casse.
✅ Les cibles K.O. réapparaissent après 2 s — farm sans fin.

AWDMonster + bestiaire zone 1 — les fiches prennent vie livré

Un monstre = une fiche du Bestiaire.md × les bases du stage. Forme par rôle (cube/cône/cylindre/sphère), taille par fiche (le boss est énorme), teinté de sa couleur de faiblesse, nom + PV au-dessus de la tête.

Les 8 patterns sont codés (droite, sinus, zigzag, charge-pause, flanqueur, spirale, sauteur, fouisseur — ces deux derniers attendent leurs monstres de zones 4–6).

AWDStageDirector — les vagues sans temps morts livré

Déroule le DA_Stage : 5 vagues à introduction progressive, boss en finale. Chrono inter-vague affiché ; terrain nettoyé = la vague suivante part immédiatement (ta règle « zéro attente »). Statut au-dessus du mur : « Vague 3/5 — 6 ennemis — prochaine : 8s ».

Hit response — le ressenti d'impact livré

Local (UWDHitResponseComponent) : flash blanc du mesh, knockback à l'impact, chiffres de dégâts colorés avec FAIBLESSE!/résisté.
Global (UWDGameFeelSubsystem) : hitstop (micro-gel du temps) + vibration manette — déclenchés sur les coups de faiblesse et les morts (gros ralenti sur la mort du boss). Switcher sur le bon élément se SENT. Camera shake viendra avec les assets.

100 % = ⭐⭐⭐    ≥ 66 % = ⭐⭐    ≥ 33 % = ⭐    < 33 % = 0 (victoire quand même)
Multiplicateur de récompenses : ×1 / ×1,25 / ×1,5 / ×2

Défaite (mur détruit) → message, terrain nettoyé. Dans les deux cas, le stage se relance après quelques secondes (le retour au menu = étape 6). C'est la boucle try and become stronger jouable de bout en bout.

Comment tester dans Unreal — Étape 5

La boucle complète (10 minutes)

1. Ouvre L_Sandbox → World Settings → GameMode Override → WDStageGameMode → Play.

✅ Écran de chargement : fond sombre, « CHARGEMENT… », barre qui se remplit, puis fondu vers le jeu — le mur gris est derrière toi, les vagues partent ~3 s après.
✅ Bouclier de départ : au lancement des vagues, « SKILL DU MUR : Bouclier de départ ! » — le mur affiche [Bouclier 600] (15 % de 4000, niveau debug 4).
✅ Répartition : les monstres ne convergent plus vers le centre — chacun marche vers le point de façade le plus proche de lui.
✅ Onde de répulsion : laisse un monstre frapper le mur — annonce + cercle turquoise au sol, tous les monstres proches sont repoussés de 700 uu et reviennent.
✅ Auto-réparation : laisse les PV tomber sous 25 % (≈ sous 1000) — le mur se soigne de +25 % une seule fois. Elle peut même sauver d'un coup fatal.
✅ Victoire : nettoie les 5 vagues — « VICTOIRE ! ★★☆ — Mur 71% — Récompenses ×1.50 » selon les PV restants, puis le stage se relance (re-chargement → re-fondu).
✅ Défaite : laisse mourir le mur (il devient noir) — « DÉFAITE — LE MUR EST TOMBÉ », terrain nettoyé, relance auto.
✅ Niveau du mur : sur le GameMode (Blueprint enfant ou Détails), WallLevel 1 = aucun skill, 4 = les trois. wd.Debug.Draw 0 coupe tous les textes.

Étape 6 — Ce qui est implémenté ✓

Le loot vivant — drops, expiration, aimant livré + 2 tests

Chaque monstre vaincu éparpille ses drops (GDD §7) là où il meurt : or (doré), XP (vert), ressource élémentaire de sa faiblesse (couleur de l'élément). Chaque drop jaillit du cadavre avec un rebond décroissant vers son point de chute autour du monstre — et n'est pas aimantable tant qu'il est en l'air (la collecte se mérite). Les drops vivent 10 s puis expirent (clignotement les 3 dernières secondes) — ramasser ou continuer à tuer, la vraie décision.

L'aimant de l'héroïne (UWDMagnetComponent) attire tout ce qui entre dans son rayon — rayon qui grandit avec le niveau du personnage. Le GameMode comptabilise la course ; en fin de stage le butin est appliqué × le multiplicateur d'étoiles (arrondi AU-DESSUS), et toujours conservé en défaite (×1) — « perdre fait progresser ».

Tables de drops dans les fiches monstres (le Rempart paie mieux, le boss est un jackpot : 60–80 or, 50 XP, 4 fragments garantis). Tier des ressources : Fragments en Normal — Cristaux/Noyaux avec les modes Hard/Enfer (étape 7).

UWDProgressionSubsystem + UWDSaveSubsystem — l'état méta et les 5 slots livré + 3 tests

Progression : or, ressources (élément × 3 tiers), XP/niveau du perso, niveaux d'armes 1–100 (coût : or + matériau de l'élément ; Fragments ≤40, Cristaux ≤70, Noyaux ensuite), niveau du mur, étoiles par stage×mode (le meilleur score est gardé). Un échec d'achat ne dépense jamais rien. Le niveau d'arme augmente réellement les dégâts en jeu (+8 %/niveau debug) et le niveau du perso agrandit l'aimant.

Sauvegarde : 5 slots disque (WDSlot_0..4), auto-load du slot au démarrage, auto-save après chaque stage et chaque amélioration. Round-trip sérialisation testé en mémoire.

Hub, pause, résumé — la boucle complète au pad livré

AWDHubGameMode + UWDHubWidget : le QG minimal — portefeuille, amélioration du mur et des 7 armes (boutons grisés si trop pauvre), 5 slots, qualité graphique, langue, « LANCER LE STAGE 1 ». Le lancement recharge la même map en mode stage (?game=) — aucune map dédiée à créer.

UWDPauseWidget : P (ou Échap hors PIE, Start à la manette) — reprendre / abandonner (= défaite, loot conservé). UWDStageSummaryWidget : l'écran de dopamine — verdict, étoiles, butin détaillé × multiplicateur (+ bonus d'or fixe par étoile), XP, puis Rejouer ou Quartier général.

UWDSettingsSubsystem : langue (SetCurrentCulture, persistée), volumes (stockés, routés vers l'audio à l'étape 7), qualité (scalabilité UE) — et au premier lancement : benchmark matériel → préréglage auto. Config utilisateur, indépendante des slots.

Comment tester dans Unreal — Étape 6

La boucle méta complète (15 minutes)

1. L_Sandbox → GameMode Override → WDHubGameMode → Play. Le QG s'affiche (or 0, tout au niveau 1).

✅ Lancer le stage : la map se recharge en mode stage (chargement → fondu → vagues).
✅ Le loot : chaque kill fait jaillir des billes du cadavre, qui rebondissent autour de lui — dorées (or), vertes (XP), colorées (fragments de la faiblesse). En l'air elles sont inaimantables ; une fois posées, approche-toi : elles volent vers toi. Ignore-en : elles clignotent puis disparaissent à 10 s.
✅ Le hit feel : chaque coup fait flasher ET trembler le monstre + petite secousse caméra ; coup de faiblesse = grosse secousse + micro-gel + vibration ; les monstres reculent loin du mur sous les coups (jamais à travers), les boss bougent à peine.
✅ Pause : touche P (Échap ferme le PIE — en build c'est Échap aussi ; Start à la manette) → Reprendre / Abandonner. Abandonner = défaite mais le butin reste.
✅ Résumé : à la fin — étoiles, butin × multiplicateur (défaite = ×1, tout conservé), bonus d'or par étoile, XP. « Rejouer » ou « Quartier général ».
✅ Améliorer : au QG, monte le lance-flammes (or + fragments de Feu — farm les monstres rouges !) puis rejoue : les ticks font plus mal (+8 %/niveau). Monte le mur : plus de PV et ses skills se débloquent aux niveaux 2/3/4.
✅ Sauvegarde : quitte le PIE, relance — l'or/XP/niveaux sont là (slot 1 auto). Change de slot : progression séparée.
✅ Aimant : à force d'XP (niveau 2 à 100 XP), le rayon d'attraction s'élargit visiblement.
✅ Options : qualité Basse→Épique appliquée immédiatement ; langue FR/EN (les textes restent FR tant que la localisation n'est pas compilée — étape 7).

UWDSpecialAbilityComponent — la Spéciale livré

Espace (ou gâchette gauche) : une nova de 20 tirs perçants de l'élément actif — chaîne pour la Foudre, souffle pour le Vent. Dégâts = l'arme × (4 + 0,1 × niveau) : c'est l'effet « palier 100 », plus faible à bas niveau (GDD §5.1). Une seule jauge de cooldown (30 s) partagée par les 7 armes — switcher ne la réinitialise pas. OnSpecialCast est le futur point d'accroche des cinématiques vidéo (avec les assets).

Modes Hard / Enfer + stages 1–5 de la zone 1 livré + 2 tests

Les modes structurent la montée 1–100 (GDD §2.5) : monstres ×2,2/×4,5 PV, dégâts au mur ×1,4/×2, +1/+2 résistances élémentaires bonus (jamais sur la faiblesse), drops ×1,6/×2,4 — et chaque mode droppe SON tier : Fragments / Cristaux / Noyaux (requis pour les niveaux d'armes 41+/71+). Chaîne de déblocage : stage N exige N−1 dans le même mode ; Hard exige le stage en Normal ; Enfer l'exige en Hard.

Zone 1 complète : 5 stages générés (2 types de monstres au stage 1, +1 nouveau par stage, tout le casting + la Brute au stage 5), bases de stats croissantes. Sélection stage + mode au QG, transmise au lancement (?WDStage=N?WDMode=M).

Conventions (rappel)

Sockets

GripPoint (main du perso) · Muzzle (bouche d'arme, position + direction du tir) · Hit (impact monstre) · Status (barre de vie). Tout socket absent → fallback offset, jamais de crash.

Données

Tout asset en TSoftObjectPtr dans un DataAsset · courbes UCurveFloat · états en GameplayTags · IsDataValid() partout · texte = FText dès le jour 1.

Communication

Composants indépendants · délégués sortants · câblage dans l'acteur propriétaire · chaque composant vit seul dans une map vide.
